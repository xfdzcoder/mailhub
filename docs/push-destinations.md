Push registration and delivery require canonical HTTPS URLs and unpadded base64url keys (a valid 65-byte uncompressed P-256 public key and 16-byte auth secret). Default approved origins are https://fcm.googleapis.com, https://updates.push.services.mozilla.com and https://web.push.apple.com on port 443.

Operators may replace defaults with PUSH_ORIGIN_POLICY, using the reviewed shared origin policy format: a JSON array of exact HTTPS origins, each optionally with addresses containing IP/CIDR restrictions. Include default providers explicitly when replacing the list. Private self-hosted services require explicit address ranges; approval never disables certificate validation. Tenant settings and OUTBOUND_HOST_ALLOWLIST do not grant push approval. DNS answers are all checked and the selected address is pinned for each direct connection. Redirects are refused. Connections have a 5-second deadline, requests including DNS and response consumption have a 10-second deadline, and responses are capped at 4096 bytes.

Each user can register at most 10 devices across organizations. Registration is serialized per user in PostgreSQL. Redis provides atomic per-user fixed-window limits of 20 registration attempts and 60 device sends per minute across processes; unavailable budget checks fail closed. Test sends select only the current session user's devices in the current organization. Registration never changes an existing subscription's user or organization, including unowned legacy rows.

Device migration requires the prior owner to authorize release using their current session: DELETE /api/notifications/subscribe with a JSON endpoint field releases only a row owned by that caller in the active organization. Unsubscribe in the browser before fresh registration by the new owner. Knowing an endpoint does not authorize migration. Release returns the same response for absent and foreign-owned rows; registration itself never transfers ownership.

Legacy review is non-destructive: inventory row IDs and owner/membership presence in a restricted operator environment; validate destinations and keys without sending notifications. Keep endpoint URLs, secrets and internal addresses out of tickets and logs. Invalid, unowned or unknown-provider rows remain quarantined in place: dispatch rejects them and does not rewrite ownership or delete validation failures. Review legitimate providers against the deployment policy before approving them. Ask the prior owner to authorize any replacement; do not infer ownership from endpoint possession. Only provider 404/410 responses remove expired subscriptions. Credential encryption is separate work.

Tests use generated keys and disposable mocks. Live HTTPS provider delivery requires operator-controlled sinks with trusted test certificates, Redis and PostgreSQL; unit coverage is not evidence of live provider delivery.
